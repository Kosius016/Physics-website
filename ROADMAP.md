# Roadmap: полиране на симулациите (за изпълнение от Codex/Sol)

Контекст: платформата е Next.js 15 + Tailwind v4 + KaTeX. Интерактивите живеят в
`components/interactives/`; споделената палитра и помощници са в
`components/interactives/svg.tsx` (STAGE_BG, C.*, Arrow, CurrentSymbol, PANEL_CLASS,
STAGE_CLASS, BTN_*). KaTeX CSS е зареден глобално в `app/layout.tsx`.

## Правила, които НЕ се нарушават (уроци от предишните итерации)

1. **Не пипай реда на секциите** в никоя страница — тъкмо е поправен.
2. **Не пипай PredictionQuestion гейтовете** и потока на GuidedProblem (Q1 → Q2 → стъпки).
3. **Никакви hardcoded цветове** — само `C.*` и `STAGE_BG` от `svg.tsx`.
4. **Посоки на полето**: ток ⊙ (навън) → полето обикаля ОБРАТНО на часовниковата стрелка.
   Преди commit провери срещу интерактива „Дясната ръка“ в Био-Савар §2.
5. **Не пускай `npm run build`, докато dev сървърът върви** (чупи `.next`). Спри го първо.
6. Тон: учтива мн.ч. форма („Преместете“, „Наблюдавайте“), без „ти“.
7. След всяка стъпка: `npm run build` да минава + ръчна проверка на страницата в браузър.

## Стъпка 1 (КРИТИЧНА, лесна): радиусите и токът да се визуализират

### 1а. `CircularArcField.tsx` — радиусът да се вижда
Сега `rv = 112` е константа. Направи го функция на плъзгача:

```ts
const rv = 45 + (radius - 0.05) * 380; // 0.05 m → 64 px, 0.30 m → 140 px
```

Леадовете (`leadStart/leadEnd`, scale 1.62) и ъгловият маркер (радиус 43) остават както са —
те са спрямо `rv`/центъра и ще се мащабират коректно. Провери, че при мин/макс радиус нищо
не излиза от viewBox 640×420 (центърът е cx=290, cy=205; 205−140=65 ✓).

### 1б. `LoopAxisField.tsx` — радиус + посока на тока
- Радиусът: сега елипсата е `rx=30, ry=112` константи. Направи:
  ```ts
  const aPx = 45 + (radius - 0.05) * 300; // 0.05→45px, 0.20→90px
  // елипса: rx = aPx * 0.27, ry = aPx
  // P: pX = loopX + ratio * aPx  (loopX=155; при ratio=5, aPx=90 → 605 ✓ в кадър)
  ```
  Пунктирът „a“ и ds₁/ds₂ точките да ползват `ry = aPx`. НЕ пипай логиката на dB
  стрелките (cosA/sinA) — тя е вярна и тъкмо поправена.
- Посока на тока: добави по една малка стрелка (Arrow) върху елипсата при горния и долния
  ръб, тангенциално (хоризонтално ±x според `right`), и я обръщай с бутона „Обърни тока“.
  Ток „надясно горе“ трябва да съответства на B надясно по оста (дясна ръка!) — т.е. при
  `right=true` (B в +x) горната стрелка сочи КЪМ зрителя-ляво… В 2D скица: за B по +x
  горната част на навивката носи ток „навътре в екрана“, долната — „навън“. Затова вместо
  тангенциални стрелки сложи **⊗ на горната точка и ⊙ на долната** (CurrentSymbol, r≈8,
  цвят C.warn) при `right=true`, разменени при `right=false`. Това е и физически точно.

## Стъпка 2 (ВИСОКА, лесна–средна): числата вън от сцената + край на застъпванията

Шаблонът на къщата (виж `FiniteWireAngles`, `InfiniteWireLimit`, `ProjectileMotion`):
**в SVG сцената остават само символни етикети** (I₁, dB₁, θ, a, P), а **всички числени
стойности и формули отиват в readout `<dl>` лента под сцената** (grid клетки bg-surface,
label uppercase + стойност tabular-nums).

Приложи върху: `CircularArcField` (B(O) стойността и „B = μ₀Iθ/4πa“ текста),
`LoopAxisField` (Bₓ стойността), `AmpereLoopExplorer` (Iобхв, циркулацията),
`SolenoidAmpere` (B горе вдясно — dl лентата долу вече съществува, само махни дублиращия
текст от сцената), `LorentzForceExplorer` (силата), `ParticleDeflectionLab` (r = … cm),
`ParallelWireForce` (F/L горе вдясно — има dl лента, махни дубликата).
„ПРИВЛИЧАНЕ/ОТБЛЪСКВАНЕ“ и заглавията на сцените могат да останат в SVG (не са величини).

В readout лентата стойностите се рендват с `RichText` (пример:
`<RichText text={"$B = 6.98\\ \\mu\\mathrm{T}$"} />`) — това покрива основната LaTeX цел.

## Стъпка 3 (ВИСОКА, средна): `SvgTex` — KaTeX вътре в SVG за символните етикети

Нов файл `components/interactives/SvgTex.tsx`:

```tsx
"use client";
import katex from "katex";

/** KaTeX етикет вътре в SVG сцена (foreignObject). Само за къси символи. */
export default function SvgTex({ x, y, tex, color = "#f2eff5", fontSize = 14, w = 90, h = 26, anchor = "start" }: {
  x: number; y: number; tex: string; color?: string; fontSize?: number; w?: number; h?: number; anchor?: "start" | "middle" | "end";
}) {
  const html = katex.renderToString(tex, { throwOnError: false });
  const dx = anchor === "middle" ? -w / 2 : anchor === "end" ? -w : 0;
  return (
    <foreignObject x={x + dx} y={y - h + 6} width={w} height={h} style={{ overflow: "visible", pointerEvents: "none" }}>
      <span style={{ color, fontSize, whiteSpace: "nowrap", display: "inline-block" }} dangerouslySetInnerHTML={{ __html: html }} />
    </foreignObject>
  );
}
```

Замени `<text>` етикетите-величини в сцените с `<SvgTex tex={String.raw`d\vec B_1`} …/>`:
I₁/I₂, B₁, dB₁/dB₂, B рез., r₁/r₂, θ₁/θ₂, α, a, x/a, v, Fᴮ, P, î′/ĵ′.
Etикетът на `Arrow`-стрелките: добави опционален проп `texLabel?: string` на Arrow в
`svg.tsx`, който рендва SvgTex вместо `<text>` (пази стария `label` за съвместимост).
Позициониране срещу застъпване: отмествай по посоката на стрелката —
`labelX = x2 + 14*cos(ang)`, `labelY = y2 + 14*sin(ang)`, с `anchor` според знака на cos.
Интерфейсни текстове („Случай 1/4“, бутони, легенди) остават нормален шрифт.

## Стъпка 4 (ВИСОКА, средна): FieldSuperposition — да се ВИЖДА защо „частично“

Файл: `components/interactives/FieldSuperposition.tsx`. Запази целия въпросен поток.
След отговора (`revealed`), добави към сцената:

1. **Полеви окръжности**: около всеки проводник по 2–3 пунктирани концентрични окръжности
   (`C.faint`), като едната минава ТОЧНО през P (радиус = разстоянието до P). По нея 2
   малки тангенциални стрелки за посоката (⊙ → обратно на часовниковата!). Цвят: синкав за
   проводник 1, оранжев за 2 (rgba от C.minus/C.plus с ниска алфа).
2. **Разлагане на компоненти** (само за случаите „частично“): от върха на dB₁ и dB₂
   пунктирани проекции към хоризонтала/вертикала през P; вертикалните компоненти с клас
   `animate-rise` + след 1s избледняване (добави в `app/globals.css` до `rise` втори
   keyframe `fadeout`: `to { opacity: 0.15 }` и token `--animate-fadeout: fadeout 1s
   ease-out 1s both;` → клас `animate-fadeout`). Хоризонталните остават плътни и се
   „събират“ в резултанта.
3. Малка легенда под сцената (нормален текст): „пунктир = компоненти; избледняващите се
   унищожават“.

Не добавяй нови случаи и не сменяй verdict логиката.
